# @deepseek-ai/dsh-effort-policy

[English](README.md) | 中文

## 摘要

内核会在路由声明的强度词表中解析三档等级，只在配置的验证失败时提升等级，并保持提升状态直到同一验证通过。输入输出都是普通数据，不引用 Cordis、会话或 LLM 类型，因此其他运行时可以复用。

服务把该决策应用到它可见的每个 Agent 的每个请求上，每次变化记录一条持久迁移，并把摘要请求固定在低等级上。它默认关闭：从不启用该行的部署不写入事件，也不改变任何请求。

<a id="use-this-package"></a>
## 使用这个包

从 `@deepseek-ai/dsh-effort-policy/core` 导入，并用路由声明的强度词表与观测状态调用 `decide(capability, state)`。结果会带上产生它的规则，调用方因此能记录某个请求为何以较低强度运行。

在运行时内部，启用 `effort-policy` 行后由服务自行工作：它在自己的作用域上监听、读取 `agent/request`，并返回最多只替换了 `reasoningEffort` 的提议配置。需要显式选择时调用 `setBase(session, effort)`；选择三档等级之一会设置基准，任何其他被路由声明的值（例如 `off`）原样写入且永不提升。Session Controller 与 ACP 的模型选择器都经由该方法记录选择，因此选择会改变路由基准，而不是与之竞争。

### 何时选择它

当宿主已经知道请求的用途，并需要一条一致的强度选择规则时使用。不要把它当作任务分类器：它没有提示词、没有模型，也不判断请求的含义。

### 何时不要使用

不要用它校验某个强度值是否被适配器接受。适配器仍是权威来源；内核只在被告知可用的值之间选择。

<a id="understand-the-implementation"></a>
## 理解实现

决策规则位于 `@mayberry/effort-policy-core`：协议版本与普通数据类型、把等级解析到路由声明的词表，以及优先级、操作表与证据迁移。本包依赖该包，并由 `src/core.ts` 在保持不变的 `./core` 入口下重新导出，因此非 Cordis 宿主从同一个所有者导入规则。`src/protocol.ts` 拒绝协议不一致的核心；`src/evidence.ts` 归类工具结果；`src/events.ts` 声明持久记录及其投影；`src/service.ts` 是 Cordis 适配器。

不写入规则是有意为之：当选中的等级解析为适配器默认强度时，决策不携带 `effort`，因为显式写入的默认值与适配器默认值是不同的持久化请求事实。同一规则会在没有任何决策时清除从已记录请求头继承的强度，因此已清除的升级不会继续提高下一个请求。

证据是一条已结算的工具结果，按三类归类。配置的验证器判定通过或失败；文本验证器返回错误属于基础设施问题，因为检查并未运行；配置的变更类工具与未列出的 shell 命令推进工作区修订号，而配置的只读模式保持修订号不变。失败会开启一次升级，携带验证器标识（`tool`、参数、工作目录）以及当时的修订号。匹配与标识都读取移除 `ignoredArgumentKeys` 之后的参数——默认移除 `description`，因为命令标题并不改变命令本身——因此调用方给同一个检查换个标题后，仍是在通过或失败同一个检查。只有当标识相同、观测更晚、且此后没有发生变更时，通过才会清除它。

持久记录是由 `effort/decision` 事件折叠而成的 `effort` 会话投影，因此恢复的会话无需读取请求头即可重建未解决的失败。服务在每个请求上通过 `ctx.root` 读取该投影：服务缺失、投影未注册或记录未通过投影模式校验，都属于依赖不可用，而不是基准状态。策略最近一次成功读取的状态会在这种失败中保留；没有任何已保留状态的会话会显式报错，因为猜测基准会降低一个未知等级。

被委派的子 agent 从它创建时携带的信息启动。`AgentOptions.effortOperation` 固定起始等级（`plan`／`review` 为 `deep`，`mechanical` 为 `low`，其余为 `standard`）；委派工具显式给出的强度会覆盖它，并作为确切起始强度原样写入，因此永不升级。该 Session 上已记录的选择或基准优先于二者，因此子 agent 自身的升级仍从其操作等级开始。委派工具（`dsh-tool-subagent`）拥有面向模型的字段，并在其 `effortPolicy` 标志开启而本服务缺失或被禁用时拒绝启动委派。

监听器归属按 Agent 与依赖代次划分。一个代次为每个存活 Agent 挂载一个监听器，在 Agent 释放时释放它，并在该代次卸载或策略自身释放时释放全部监听器。替换后的代次会挂载到它启动时已存在的 Agent，以及此后创建的 Agent。

<a id="model-experience"></a>
## 模型体验

### 请求强度随验证结果变化

#### 模型看到什么

请求的 `reasoningEffort`：策略可能把它设为解析出的等级、留在适配器默认值，或将其移除。它从不改变 `provider`、`model` 或其他任何请求字段，也不增加提示词文本或工具。

#### 令牌影响

只有配置的基准与未解决的失败会改变推理令牌。已清除的升级会让下一个请求回到适配器默认值，而 `off` 这类精确选择会按所选值发送。

#### KV Cache 影响

无。策略只改变一个请求控制项，消息前缀保持不变。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与待办

- **必读事件会让已启用的会话在旧构建中无法读取** —— `effort/decision` 无法标记为可忽略，因此写入它的构建之前版本的构建会拒绝该会话。从不启用策略的部署不写入任何内容。
- **修订号按工作区计算且会过度近似** —— 未列出的 shell 命令计为变更，因此合法的通过可能被判为过期，升级会保持到下一次匹配的通过。
- **每个请求都要付出一次能力查询** —— `resolveModelInfo` 在循环自身的准备之外按请求运行；由远程目录支撑的路由每一步都要付出这次查询。按路由缓存一回合是已记录的备选方案，尚未实现。
- **在策略查询与循环绑定之间被替换的路由会按路由默认值分派** —— 循环丢弃不被声明的强度、记录一条警告并重新绑定，因此该步骤运行的等级与策略的决定不同；已记录的 header 记录的是实际分派的值。
- **不可读记录只在同一个策略实例内保留上次等级** —— 重启后遇到无法解码的记录时没有可保留的上一状态，请求会显式失败，而不是退回基准。
- **冷恢复的子 agent 会丢失其操作** —— 委派描述符只保存提供方、模型与强度，因此恢复后的子 agent 从配置的基准等级启动，而不是其原始操作；被继承的强度属于确切起始强度，永不升级。
- **进程外子 agent 没有操作** —— SDK 提供方只复制四个具名路由字段，因此 `effortOperation` 与 `effortInherited` 不会跨越进程边界，这类子 agent 从配置的基准等级启动。
