# 智能体笔记：委派用量归属于委派方

状态：已实现

[English](2026-10-23-delegated-subagent-usage.md) | 中文

## 问题

一次委派会运行一个子 Session，它消耗的每个 token 都结算在子日志里。`tokenUsage` 与 `usageByRoute` 只折叠单个 Session 自身的事件，因此对话的用量读数只覆盖它自己发出的请求。一个委派了三项分析的对话实际计费 162.7M 个 token，却只报告 38.0M；用户把它与供应商用量导出对比时，看到 4.3 倍的差距，且无从解释。

## 决定

`packages/subagent/subagent/src/delegated-usage.ts` 在本地子执行周期结算时向委派方父会话追加一条 `subagent/usage` 记录。该记录携带该周期的供应商计数，按 `(turn, step)` 去重并按每次结算所用路由分组，同时并入子会话自身的嵌套归属，使根父会话看到整棵树。`SubagentManager.attributeDelegatedUsage` 在捕获结果之后写入，并包含任何拒绝，因此计量从不改变运行结果。

`tokenUsage`（状态版本 3）与 `usageByRoute`（状态版本 2）把该记录折叠进计费总量与按路由计数。它们不改动最后样本位与 `contextPressure`：父会话为其子请求付费，而其自身上下文读数仍只属于自己。版本提升会丢弃在该折叠之前生成、总量偏低的投影缓存行。

## 验证

折叠本笔记所涉对话的存储日志可复现供应商导出：父会话及其三个子会话合计 162,696,320 个 token，而该小时导出为 164,167,633 个，差值为尚未走完的小时部分。`pnpm exec vitest run packages/subagent/subagent packages/llm/token-meter` 通过，共 876 个测试，覆盖周期折叠、父会话写入、两个投影，以及 activation-policy 中“子运行只向父日志添加其目录条目和一条用量归属”的断言。

## 考虑过的替代方案

**客户端读取时汇总。** 侧栏可以对已加载的后代投影求和。这会让所有非 UI 消费方（SDK、ACP、JSON 流）继续少计，并且在子 Session 未加载时给出不完整的数字。

**在工具结果中归属。** 把用量放进 `tool/result.meta` 无需新事件，但折叠方此后要解析由产出工具拥有、对核心不透明的展示字段，使跨包契约变成隐式的。

**每次助手结算追加一条记录。** 崩溃安全且无需周期记账，但父会话每个子模型调用一条事件——一小时委派约 230 条记录。

## 后果

对话的用量与花费读数现在等于账号为整棵树实付的金额，侧栏无需额外界面即可报告委派花费。继续执行可续接子会话时只追加后续周期，因此跨重启的总量仍精确。宿主进程崩溃导致周期永不结算时，其用量无法归属，因为只有结算才写记录。父日志因此携带子会话的路由标识，第二个供应商的模型名会与自身一起出现在父会话的 `usageByRoute` 计数中。本决定扩展了[投影 token 用量](2026-07-29-projected-token-usage-and-request-context.zh.md)所定义的单 Session 自身请求读数；该单元、其表层定价与 `contextPressure` 均未改变。
