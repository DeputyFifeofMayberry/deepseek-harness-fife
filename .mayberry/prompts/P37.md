## P37 — Verify a change without gaming the tests

**Use when:** An approved change needs task or integration evidence.

**Inputs:** Exact candidate/diff, accepted behavior, QUALITY policy, approved commands and resource/permission limits.

```text
Verify [candidate/change] against its accepted behavior and QUALITY.md. Inspect current state and test/configuration diffs. Select the cheapest reliable checks and broaden for shared or uncertain impact. Run only authorized commands in safe isolation. Confirm discovery and candidate identity; preserve first failures, retries, skips, output and unrun checks. Do not weaken assertions, expected values, fixtures, snapshots, recordings, selection, tolerances, baselines or workflows to obtain green results. Propose an incorrect oracle separately with independent justification and the required approval. Use only approved repair scope and attempt/time/cost limits; stop on repeated failure without new evidence, unresolved expectations, invalid environment or new authority needs. Return a W13 evidence record, remaining gate and affected regression registration. Do not deploy or infer release readiness from task checks.
```
