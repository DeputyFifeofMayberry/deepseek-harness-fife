## P06 — Architecture explanation

**Use when:** A design or subsystem is difficult to explain.

**Inputs:** Affected workflow, current code and architecture record.

```text
Explain [system/workflow] using its actual code and current architecture record. Start with an ordinary user action and follow input, decisions, state, storage, external calls and output. Define necessary technical terms in plain English. Identify who owns each important state change and what happens on failure or overlap. Point to inspected paths/symbols and distinguish uncertainty. Do not redesign or edit the system. Finish with three questions I should be able to answer in my own words before authorizing a consequential change.
```
