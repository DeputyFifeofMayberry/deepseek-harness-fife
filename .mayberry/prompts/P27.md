## P27 — Project status handoff

**Use when:** You need a project-level view of progress and blockers.

**Inputs:** Canonical project docs, issues, repository state and release evidence.

```text
Create a current project-status handoff from [canonical records and repository]. Reconcile actual implementation, verification and release state against the roadmap. Separate completed/validated/released work, active scope, blockers, deferred ideas and actionable debt. Link evidence, decisions and the next milestone gate. Identify stale/conflicting records and uncertainties instead of choosing silently. Do not infer progress from generated code or commit count alone. Return a concise status record with next safe priorities; do not mutate code or publish it.
```
