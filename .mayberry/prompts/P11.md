## P11 — Understand before implementation

**Use when:** You need a human authorization checkpoint.

**Inputs:** Proposed change, repository evidence and plan.

```text
Before implementing [change], explain in plain English: current behavior; problem and evidence; proposed approach; reasonable alternative; affected systems/data; risks; acceptance checks; regression protection; recovery; and Done. Inspect the actual relevant code instead of guessing. Mark facts, assumptions, proposals and unrun checks separately. Scale the detail to consequences. Tell me which unanswered questions block the risky action and what safe investigation would answer them. Do not edit code. End with a short teach-back question to confirm I understand the decision.
```
