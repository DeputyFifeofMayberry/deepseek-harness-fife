## P36 — Establish the verification operating system

**Use when:** A maintained project needs clear commands, cadence and gates.

**Inputs:** Repository, current QUALITY/README, runner/CI configuration, risk profile and permissions.

```text
Inspect [repository]'s actual test runners, commands, CI, fixtures and release process before proposing changes. Build W34 for its real consequences. Identify the smallest useful suites, exact commands, triggers, selection/broadening rules, environments/credentials, runtime/cost bounds, reports and required/advisory gates. Check discovery, unexpected skips, unsafe destinations, local/CI differences and whether failure reaches the intended decision. Define isolation, first-failure/retry handling, quarantine ownership/expiry/alternative protection and protected agent actions. Prefer existing runner features; do not add Docker, frameworks, distributed execution or paid services without demonstrated need and approval. Propose bounded changes to QUALITY.md, not duplicate policy. Distinguish inspected/proposed/actually executed evidence. Do not edit or run unapproved commands.
```
