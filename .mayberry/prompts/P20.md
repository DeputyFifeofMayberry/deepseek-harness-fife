## P20 — Migration planning

**Use when:** Persistent state or data format is changing.

**Inputs:** Current/target schemas, code versions, data, constraints and recovery goals.

```text
Plan [migration] without writing to valuable data. Inspect current/target formats, old/new code compatibility, concurrent writers and irreversible transformations. Define engine-appropriate backup, isolated restore evidence, rehearsal fixtures, checkpoints, rerun/idempotency behavior, semantic validation and failure branches. Distinguish code rollback, data restore and roll-forward; account for writes after backup. Identify exact-target confirmation and human approval gates. Do not assume a down script is recovery. Return a migration runbook and unresolved blockers.
```
