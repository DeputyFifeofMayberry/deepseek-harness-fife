## P40 — Investigate performance before optimizing

**Use when:** A delay, resource problem or cost concern needs causal evidence.

**Inputs:** Symptom, candidate/baseline, representative permitted data, environment and investigation limits.

```text
Investigate [symptom] before editing. Define the affected user operation, workload, timing boundary and correctness contract. Establish exact baseline, dataset/environment/build versions, cold/warm assumptions, repetitions and raw evidence. Choose CPU/allocation/heap/I/O/network/query/trace/UI evidence that can distinguish the limiting resource; state alternatives and instrumentation limits. Propose one bounded hypothesis with a predicted effect, smallest change, permission/resource bounds and correctness checks. Define a comparable candidate experiment and meaningful decision threshold before results. Do not add caches, parallelism or a new architecture without supporting evidence; no invented timings or causal claims. Return W36 with observed facts, unresolved questions and next discriminating measurement. Run only approved diagnostics; do not touch valuable data.
```
