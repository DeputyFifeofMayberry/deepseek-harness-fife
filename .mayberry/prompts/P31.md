## P31 — Data-model challenge

**Use when:** Persistence or a schema proposal needs review before it becomes a contract.

**Inputs:** Requirements, existing schema/data examples, access patterns, ownership and migration constraints.

```text
Inspect [requirements, current model and representative records]. Explain entities, stable identities, relationship cardinality, authoritative writers, constraints, derived/cached/snapshot values, real queries, index tradeoffs, transaction boundaries and deletion/retention behavior. Walk through create/edit/query/duplicate/concurrent/delete cases. Compare the simplest adequate persistence alternative; do not add a server database for hypothetical scale. Identify old/new compatibility and link material stored-data changes to a migration/recovery plan. Distinguish verified schema behavior from assumptions. Return a reviewed model, evidence-based risks, checks and design gates using W29. Do not execute migrations or modify valuable data.
```
