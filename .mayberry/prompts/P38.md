## P38 — Plan supported updates

**Use when:** Existing installations or independently updated components need a support promise.

**Inputs:** Current/historical artifacts, formats/settings, supported platforms, distribution, users and recovery constraints.

```text
Inspect [product]'s real installed states and update mechanism. Build W35 separating maintenance support, runtime compatibility and upgrade sources. Map relevant application/data/configuration/platform/API/plugin/updater-trust versions. Recommend the smallest support matrix with source artifact/fixture provenance, direct routes where practical and justified intermediate application stops. Define eligibility, activation/restart, writer control, stable/pilot/channel switching, trust/key transition, interruption, safe rerun, downgrade and post-update-write recovery limits. Include refusal or export when an update is unsupported/impossible, and explicit retirement/communication owners. Select representative boundary and prior-upgrade histories and define exact-candidate rehearsal evidence. Link W19/W17/W18 rather than creating a second release authority. Do not install, migrate, publish, alter support promises or access signing credentials.
```
