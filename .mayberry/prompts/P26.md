## P26 — Documentation synchronization

**Use when:** A completed change affects durable project knowledge.

**Inputs:** Final diff, verified results and canonical document map.

```text
Synchronize project documentation for [completed change]. Inspect the final diff, actual commands/results and canonical document map. Update only affected verified facts in the authorized documentation files: product behavior, setup, architecture/data ownership, quality/recovery expectations, decisions or release notes. Link rather than duplicate. Preserve accepted decision history and known limitations; mark unresolved facts instead of inventing them. Do not change application code, create unnecessary documents or paste the chat history. Return changed documents and the evidence supporting each update.
```
