## W09 — Feature / Change Brief

**Purpose:** Carry one change through the feature loop.

**Use when:** Standard work or the controlling brief for a Deep change. **Skip when:** Quick work can answer the relevant points in a short note.

| Prompt | Your response |
|---|---|
| **Identity, level and product link**<br>Task ID; baseline; Quick/Standard/Deep and why; requirement/milestone. |  |
| **Current state, problem and evidence**<br>Actual behavior, desired behavior, inspected path and relevant observations. |  |
| **Scope and non-goals**<br>Allowed behavior/files; unrelated work preserved; explicit exclusions. |  |
| **Approach, alternatives and steps**<br>Small coherent implementation; important assumptions and gates. |  |
| **Risks, permissions and recovery**<br>New dependencies/data/security; separately approved actions; undo/restore path. |  |
| **Acceptance, regression and Done**<br>Accepted behavior; reusable protection or justified omission; task checks and suite registration; separate integration/release evidence including applicable upgrades/performance; no mandatory extra forms. |  |
| **Results, review, records and checkpoint**<br>Actual checks; findings/disposition; docs changed; commit/release state. |  |

**Close the worksheet when:** Ready: important assumptions, scope, proof and authority are defined. Task Done: accepted behavior, registered reusable protection or justification, current required checks, reviewed gate/test changes and affected records; later release evidence remains explicit.

**Use with:** Chapters 1/6/8; [P10](../prompts/P10.md#p10)/P11.
