## W21 — Periodic Maintenance Review

**Purpose:** Keep the system supportable with a manageable routine.

**Use when:** A reused or distributed project. **Skip when:** A truly retired/disposable project after safe resource cleanup.

| Prompt | Your response |
|---|---|
| **Scope, owner and cadence**<br>Supported versions/states, audience and owner; each recurring check has a drift/accumulation reason, justified interval/event and response. |  |
| **Dependencies and platform changes**<br>Affected versions, advisories, compatibility; update/defer/revisit evidence. |  |
| **Data and recovery**<br>Backup/restore health, storage growth, upgrade-source support and historical artifact/fixture provenance, including prior-upgrade histories. |  |
| **Quality and behavior**<br>Broken/flaky/slow tests, first failures/retries, quarantine owner/issue/expiry, explicit lost protection, alternative verification, suite runtime and recurring bugs. |  |
| **Documentation and setup**<br>Fresh setup, actual commands/discovery, supported targets, obsolete fixtures, benchmark workload/environment validity and architecture drift. |  |
| **Operational commitments**<br>User reports, privacy/log retention, hosting/cost ownership, API/model changes and eval drift where relevant. |  |
| **Benchmark and support health**<br>Workload/baseline provenance, raw trends/noise, approved threshold changes, update adoption evidence when justified, obsolete supported-state cases and next revalidation. |  |
| **Actions and closure**<br>Prioritized owner/action/gate; link issues rather than creating a duplicate backlog. |  |

**Close the worksheet when:** Every repeated task catches a meaningful failure and has a response.

**Use with:** Chapter 16; [P25](../prompts/P25.md#p25)/P27.
