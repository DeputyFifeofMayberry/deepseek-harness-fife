## W10 — Human Checkpoint

**Purpose:** Prevent blind authorization.

**Use when:** A meaningful implementation or changed consequential assumption. **Skip when:** For Quick work, answer only the relevant subset in your own words.

| Prompt | Your response |
|---|---|
| **What and why?**<br>What changes, why now, and which outcome/requirement does it support? |  |
| **Current state and insufficiency**<br>How does it work today, what is inadequate, and what evidence shows it? |  |
| **Approach and alternative**<br>What are we choosing and why over a reasonable simpler option? |  |
| **Impact and regression**<br>What existing behavior, installed states or performance limits could change? Which important contracts must remain? |  |
| **Proof and Done**<br>Which checks run now versus integration/release, and what independent expectation or baseline governs them? What evidence closes this decision? |  |
| **Recovery and permission**<br>Does recovery require data/configuration restoration as well as old code? Who may change expectations, support policy, channels, signing or performance limits? |  |
| **Teach-back and decision**<br>Explain without quoting the agent. Approve / investigate / revise / escalate. |  |

**Close the worksheet when:** You can explain the relevant answers in your own words, and every consequential unknown is either resolved or explicitly gated before implementation is authorized.

**Use with:** Chapter 1; [P11](../prompts/P11.md#p11); [C04](../QUICK_REFERENCE_CARDS.md#c04).
