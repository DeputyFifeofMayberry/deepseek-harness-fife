## W20 — Post-Release and Incident Review

**Purpose:** Learn from actual operation and significant failures.

**Use when:** After a meaningful release or incident. **Skip when:** An uneventful small patch can keep a short release observation note.

| Prompt | Your response |
|---|---|
| **Version, event and impact**<br>What happened, who/what was affected, and what is known versus suspected? Link [W31](W31_outcome_measurement_and_product_decision.md#w31) when reviewing usefulness rather than only incident health. |  |
| **Timeline and evidence**<br>Observations and actions with timestamps; preserve useful records. |  |
| **Containment and recovery**<br>Who authorized what, result, and whether it was mitigation or correction. |  |
| **Cause and contributing factors**<br>Link [W11](W11_Bug_Investigation.md#w11)/W12; do not invent a single cause where interactions remain uncertain. |  |
| **Verification after recovery**<br>Actual user workflow, data integrity, remaining failures and signals. |  |
| **Follow-up actions and owners**<br>Specific prevention and maintenance; decision/event/date where known. |  |
| **Communication and learning**<br>Affected-user update; documentation/guardrails changed; effectiveness check. |  |

**Close the worksheet when:** Follow-ups are actionable and proportional, not a list of generic promises.

**Use with:** Chapter 16; [P23](../prompts/P23.md#p23).
