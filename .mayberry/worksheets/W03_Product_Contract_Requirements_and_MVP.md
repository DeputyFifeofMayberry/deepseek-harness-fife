## W03 — Product Contract, Requirements and MVP

**Purpose:** Define behavior before implementation.

**Use when:** A product or meaningful capability is being specified. **Skip when:** The accepted contract already covers this isolated change.

| Prompt | Your response |
|---|---|
| **Outcome, users and workflow**<br>Link [W01](W01_Project_Idea_and_Problem_Canvas.md#w01); describe the first complete useful path. |  |
| **Requirements and acceptance**<br>Use stable IDs; state observable behavior and corresponding evidence. |  |
| **Failure and edge behavior**<br>Empty, invalid, partial, unavailable, interrupted, concurrent or denied states as relevant. |  |
| **Quality and constraints**<br>Performance conditions, supported platforms, privacy/data integrity and accessibility; [W28](W28_user_flow_interaction_states_and_usability.md#w28) interaction and [W31](W31_outcome_measurement_and_product_decision.md#w31) outcome links where relevant. |  |
| **MVP: Now / Later / Not planned**<br>Explain inclusion by outcome, learning or necessary protection. |  |
| **Traceability**<br>Requirement → milestone/feature → verification case; link existing records. |  |
| **Approval and revision trigger**<br>Who accepts scope? What evidence would cause a change? |  |

**Close the worksheet when:** Each current requirement has a check and does not conceal an unapproved technology choice.

**Use with:** Chapter 2; [D03](../DECISION_AIDS.md#d03)/D04; [P04](../prompts/P04.md#p04).
