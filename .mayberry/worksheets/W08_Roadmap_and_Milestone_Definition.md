## W08 — Roadmap and Milestone Definition

**Purpose:** Connect product outcomes to executable slices.

**Use when:** Planning the project or revising a meaningful milestone. **Skip when:** A small task already fits a current milestone.

| Prompt | Your response |
|---|---|
| **Product outcome and MVP boundary**<br>Link accepted requirements and non-goals. |  |
| **Milestones and exit evidence**<br>Describe usable outcomes; avoid a list of technologies to install. |  |
| **Dependencies and risk-first sequence**<br>Which experiment/decision must precede which work? |  |
| **Next vertical slice**<br>User action → useful result; link its requirement and Change Brief. |  |
| **Ready and Done for this milestone**<br>Inputs/gates to begin; evidence and operational state to finish. |  |
| **Deferred detail and backlog**<br>State what remains intentionally undecided and when to elaborate it. |  |
| **Owner, status and replanning trigger**<br>Use real dates only when agreed; record what could change sequencing. |  |

**Close the worksheet when:** The next task is detailed enough; distant milestones are not fictional implementation scripts.

**Use with:** Chapter 6; [P09](../prompts/P09.md#p09)/P10.
